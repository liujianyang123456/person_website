Git 是 Agent 开发的安全绳

2026-09-20

Agent 可以一口气修改很多文件，也可能改错。没有版本管理时，目录里很快就会出现 网站-最终版2 和 网站-这次真的能用。

我的做法

  • 提交前先看 git diff，确认 Agent 到底改了什么；
  • 每个完成的功能单独 commit，形成可以恢复的检查点；
  • 实验性改动放进分支，避免污染 main；
  • 需要回滚时直接回到上一个 commit，而不是手工翻文件夹。

回滚比「最终版2」可靠：它精确、可重复，并且永远不会改错文件。

和 CloudBase 的配合

代码推送到 GitLab 后，CI 会先跑构建和检查，全部通过才把 public/ 部署到腾讯云 CloudBase。Git 负责「改错了能退回去」，CI 负责「有问题的版本上不了线」。
